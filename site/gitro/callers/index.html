    What the caller does
    
        
    Any program that can write and read files in the folder can be a caller: an agent with a file tool, a script,
            a scheduled task.
    
        
      
            
    1. Write the request, one argument per line, to a new file in the folder, such as req-1.tmp.
                log, --oneline, -8 asks for gitro log --oneline -8.
      2. 
            
    2. Rename it to req-1.req. The server picks up only .req files, so it never reads half
                a request.
      3. 
            
    3. Wait for req-1.out. Its first line is # gitro exit=<code>: <request>, and the
                command's output follows. The server writes it under another name and renames it, so it's whole when it appears.
      4. 
            
    4. Read it and delete it. The server removes the request itself, and any answer left over after an hour.
      5. 
        
    
        
    The folder's gitro-server.json says which repository is served and whether the server is still running,
            and a help serve request answers with these steps, so a caller can learn the protocol from the folder alone.
