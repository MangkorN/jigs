Callers write requests here and read the answers. gitro creates the folder if it doesn't exist. Keep it outside the repository: callers need only this folder. Typing a path suggests its folders: Tab or Enter takes one.

How this page reaches your machine

gitro ui starts a small companion process on your computer, in the background, and opens this page. It listens on 127.0.0.1 only, and answers only pages opened from a file or from the hosted site, and only with its token. It can do one thing: run gitro. On Windows it's a PowerShell script; on macOS and Linux it needs Python 3.

While it runs, it writes its port and token to .gitro-ui/session.js in your clone. This page, opened from the clone, reads that file every couple of seconds, which is how it connects by itself. The hosted page can't read your files, so gitro ui -o hosted opens it with a link that carries the token.

Each server it starts is gitro serve -k, which keeps a copy of every response for an hour. That's how this page can show you what a caller asked and what it got back, even after the caller has collected its answer.

Stopping the companion, with gitro ui stop or the button above, stops every server it started. A server also stops on its own if the companion is closed or crashes.
